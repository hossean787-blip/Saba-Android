# گزارش مرحله‌های ۱ تا ۴ — نسخه ۱۰ صبا

## ۱) بازبینی کد و دیتابیس
- رابطه فاکتور/مشتری با کلید مرکب شرکت و مشتری تعریف شده است تا ارجاع فاکتور به مشتری شرکت دیگر در SQLite رد شود.
- ذخیره پیش‌نویس و نهایی‌سازی در تراکنش Room انجام می‌شود؛ نهایی‌سازی وضعیت فاکتور، کسر سهمیه و درج سابقه مصرف را یکجا انجام می‌دهد.
- شماره فاکتور در هر شرکت شاخص یکتا دارد و سابقه مصرف سهمیه برای هر فاکتور شاخص یکتا دارد.
- انتقال سهمیه از شناسه عملیات یکتا استفاده می‌کند و تکرار همان درخواست با همان مشخصات را بی‌اثر می‌کند.
- موارد باقی‌مانده: آزمون یکپارچه Room، مهاجرت و بازیابی دیتابیس، آزمون هم‌زمانی روی دستگاه و بررسی دقیق تمام مسیرهای رابط کاربری.

## ۲) آزمون منطق مالی و سهمیه
- تست‌های قبلی محاسبه خالص/مالیات/مبلغ نهایی، تعداد صفر و تخفیف نامعتبر حفظ شدند.
- تست‌های تازه برای گرد کردن مالیات تا ریال و سرریز ضرب اضافه شدند.
- تست‌های قواعد مجوز برای طرح سالانه آزاد، طرح ماهانه، تعداد ثابت و زمان انقضا اضافه شدند.
- این تست‌ها به سورس افزوده شده‌اند ولی در این محیط اجرا نشده‌اند؛ نتیجه سبز JUnit ادعا نمی‌شود.

## ۳) چندشرکتی، مجوز و امنیت
- سیاست دامنه برای طرح‌های ماهانه، سه‌ماهه، شش‌ماهه، سالانه آزاد و تعداد ثابت اضافه شد.
- این سیاست صرفاً اعتبارسنجی درخواست است؛ صدور مجوز معتبر، پرداخت، ورود کاربر، نقش‌ها و کنترل سمت سرور هنوز پیاده‌سازی نشده‌اند.
- شناسه خریدار در نسخه فعلی ورودی محلی است و احراز هویت نیست. بنابراین این نسخه برای فروش تجاری یا نگهداری داده حساس آماده نیست.
- پیش از عرضه باید API سمت سرور با مجوز امضاشده/قابل اعتبارسنجی، کنترل مالکیت شرکت، ثبت رویداد ممیزی، محدودیت نرخ، پشتیبان‌گیری و سیاست حفظ اسرار طراحی شود. کلید خصوصی/گواهی نباید داخل APK قرار بگیرد.

## ۴) اتصال سامانه مؤدیان
- مرز برنامه‌نویسی `TaxpayerGateway` و پاسخ‌های وضعیت اضافه شده است تا اتصال رسمی از منطق UI و فاکتور جدا بماند.
- `UnconfiguredTaxpayerGateway` عمداً ارسال واقعی را انجام نمی‌دهد و وضعیت `NOT_CONFIGURED` برمی‌گرداند؛ هیچ موفقیت ساختگی ثبت نمی‌کند.
- اتصال واقعی در این نسخه انجام نشده است. برای پیاده‌سازی باید نسخه جاری مستندات رسمی، قرارداد API، قالب و اعتبارسنجی صورتحساب، روش احراز هویت/گواهی، محیط آزمایشی و اطلاعات دسترسی مجاز فراهم شود. سپس باید ارسال، استعلام، خطاها، تکرار امن درخواست و امضای داده طبق همان مستندات پیاده‌سازی و آزموده شوند.

## وضعیت ساخت
- فایل ZIP پس از بسته‌بندی بررسی می‌شود.
- Android Gradle Plugin 8.7.3 و Kotlin 2.0.21 به JDK 17 و Android SDK نیاز دارند؛ محیط فعلی Windows 7 + Java 8 کاربر برای پیکربندی حاضر مناسب نیست.
- کامپایل، اجرای تست‌ها، نصب APK و اتصال شبکه در این مرحله انجام نشده‌اند.
