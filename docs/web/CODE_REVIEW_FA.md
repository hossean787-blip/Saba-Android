# گزارش بازبینی صبا ۱۹

تاریخ: ۲۰۲۶-۱۰-۲۷

## دامنه و شواهد

آرشیو اصلی شامل یک فایل HTML دارای CSS و JavaScript درون‌خطی و ۲۱ فایل مستندات/فهرست است. سورس Kotlin، پروژهٔ Gradle، پایگاه دادهٔ Room یا آزمون‌های دامنهٔ اشاره‌شده در مستندات قدیمی داخل این آرشیو وجود ندارند. هیچ نتیجهٔ ساخت اندروید از گزارش‌های قبلی به این نسخه تعمیم داده نشده است.

## اصلاحات انجام‌شده

| یافته | علت | اصلاح |
|---|---|---|
| پشتیبان ناسازگار جایگزین دادهٔ سالم می‌شد | بررسی صرفاً وجود چند آرایه و نوع یک عدد | اعتبارسنجی نوع رکورد، شناسه و یکتایی، روابط شرکت/مشتری، وضعیت فاکتور، مبالغ، سهمیه و تنظیمات پیش از جایگزینی؛ تأیید کاربر برای بازیابی |
| امکان تزریق از پشتیبان در HTML | شناسه‌ها در ویژگی‌ها و وضعیت‌ها در HTML بدون escape | محدودسازی شناسه‌ها، escape ویژگی‌ها و وضعیت‌ها و رد وضعیت ناشناخته |
| انتخاب مشتری و مقصد سهمیه با refresh تغییر می‌کرد | بازسازی گزینه‌ها بدون نگهداری مقدار قبلی | حفظ انتخاب معتبر؛ مشتری خارج از شرکت فعال قابل انتخاب نیست |
| سرریز سهمیه | کنترل integer بدون کنترل safe integer و مجموع جدید | کنترل محدودهٔ امن برای تعداد خرید و مجموع کیف/خرید |
| وضعیت نمایشی پس از خطای ذخیره می‌توانست با دادهٔ ماندگار تفاوت داشته باشد | فقدان مدیریت خطای localStorage | بازخوانی وضعیت ذخیره‌شده، اعلام شکست و جلوگیری از پیام موفقیت |
| دادهٔ خراب ممکن بود با ثبت جدید از بین برود | تبدیل خطای خواندن به وضعیت خالی بدون محافظت | مسدودسازی ذخیره تا بازیابی معتبر یا بازنشانی صریح؛ حفظ بایت‌های دادهٔ خراب |
| مبلغ صفر در چاپ خالی بود | استفاده از `value || ''` | استفاده از `value ?? ''` |
| نگهداری کد دشوار بود | فایل فشرده و بازتعریف تابع render در افزونه | جداسازی سورس، شکست خطوط، یک تابع render و یک نقطهٔ شروع؛ سازندهٔ HTML مستقل |
| برخی فیلدها برچسب مرتبط نداشتند | label بدون for | اتصال برچسب‌های مجاور به شناسهٔ ورودی/فهرست |

اعتبارسنجی مبالغ، همان قرارداد محاسبهٔ موجود (`Math.round(net * rate / 100)`) را بررسی می‌کند؛ این اصلاح به‌معنی تأیید قواعد قانونی محاسبه، گردکردن یا نرخ مالیات نیست.

## آزمون‌ها

فرمان‌های اجراشده:

```sh
python tools/build.py
node --check src/app.js
node tests/regression.cjs
```

نتیجهٔ نهایی مرورگر: **۱۳ آزمون موفق، صفر ناموفق، صفر خطای pageerror**. خروجی کامل در `tests/results.json` است.

پوشش: حفظ مشتری، رد پشتیبان خراب و سهمیهٔ منفی، جلوگیری از سرریز، ساخت و محاسبهٔ فاکتور، تخصیص و مصرف سهمیه، جلوگیری از مصرف مجدد، تفکیک دادهٔ شرکت، لغو/تأیید بازیابی، رد شناسهٔ تزریقی و روابط/مبالغ ناسازگار، برگشت وضعیت هنگام شکست ذخیره، پایداری پس از reload، تفکیک کالا، پیمایش هر ۱۱ صفحه، چاپ مبلغ صفر، و حفظ دادهٔ محلی خراب.

چهار آزمون اولیه پیش از اصلاح روی نسخهٔ اصلی ناموفق شدند. آزمون حفظ دادهٔ خراب و آزمون چاپ صفر نیز ابتدا خطا را بازتولید کردند و پس از اصلاح موفق شدند.

آزمون‌ها با Chromium و Playwright روی سرور موقت loopback اجرا شدند. بازکردن مستقیم `file://` در مرورگر این محیط با سیاست مدیریتی مسدود بود؛ بنابراین اجرای مستقیم فایل در مرورگر شخصی کاربر جداگانه تأیید نشده است. محتوای پنجرهٔ چاپ بررسی شد؛ چاپگر واقعی یا خروجی PDF مستقل آزمون نشده است. آزمون جامع دسترس‌پذیری، موبایل واقعی، مرورگرهای دیگر و امنیت کامل انجام نشده است.

## موارد باز برای محصول حسابداری

- نبود هستهٔ حسابداری دوطرفه، دفاتر، دوره/سال مالی و گزارش‌های حسابداری.
- نبود فاکتور چندردیفی، اصلاحی/ابطالی و مدیریت حسابداری موجودی.
- ذخیرهٔ مرورگری تک‌کاربره: تب‌های هم‌زمان می‌توانند تغییرات یکدیگر را بازنویسی کنند؛ تراکنش چندکاربره و همگام‌سازی وجود ندارد.
- نبود احراز هویت و کنترل دسترسی سرور، رمزگذاری دادهٔ محلی و ثبت رویداد حسابرسی قابل‌اتکا.
- نبود اتصال رسمی مؤدیان، امضای معتبر و پرداخت واقعی.
- قالب تاریخ و شناسه‌های مالیاتی اعتبارسنجی رسمی نمی‌شوند؛ داده‌های این نسخه نباید به‌عنوان سند تأییدشدهٔ مالیاتی تلقی شوند.

این موارد در دامنهٔ پاک‌سازی نسخهٔ ۱۹ پیاده‌سازی نشده‌اند و برای تبدیل صبا به محصول حسابداری باید جداگانه طراحی و آزمون شوند.
