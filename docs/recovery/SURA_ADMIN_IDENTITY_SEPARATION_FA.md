مسیر ایجاد: ثبت‌نام مجاز در سورا با نشانی فرعی، پذیرش واقعی قوانین و تأیید ایمیل؛ یا ایجاد از طریق Auth Admin API با دسترسی مجاز و رعایت trigger پذیرش. ابزار فعلی Auth Admin createUser ندارد. ساخت مستقیم ردیف auth.users، دور زدن trigger و رمز متنی در مخزن ممنوع.
پیش‌شرط انتقال: UUID مستقل، ایمیل تأییدشده، مالکیت اثبات‌شده؛ تهیه نسخه برگشت از تعاریف زنده و نقش‌ها. تغییر gate چهار تابع sura_card_review، sura_manager_monthly_price، sura_publish_starter، sura_support_manager_act و چهار API sura-admin-api، sura-manager-api، sura-card-transfer، sura-manager-support. بررسی تمامی RPC و policyهای وابسته به نقش. اصلاح نگاشت ورود مدیر و نسخه APK؛ عدم تغییر رمز حساب عادی. انتقال نقش فقط به UUID جدید در تراکنش، دقیقاً یک admin؛ عدم حذف حساب یا سوابق ممیزی. قدیمی‌ها با نقش قبلی نباید دسترسی مدیریتی داشته باشند. نقش/توکن کاربر عادی برای API مدیریتی رد شود.
دروازه پذیرش: ورود با رمز مستقل، رد رمز حساب عادی در مدیر، رد توکن عادی در هر چهار API و مسیرهای مستقیم RPC، آزمون مدیریت اعتبار/قیمت/رسید/پشتیبانی بدون تراکنش واقعی، حفظ اطلاعات کاربر، امضای قبلی APK. تا تکمیل این موارد استقلال فعال اعلام نشود.
