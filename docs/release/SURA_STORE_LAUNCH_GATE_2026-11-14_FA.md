# سورا — وضعیت واقعی دروازه انتشار فروشگاهی (۲۰۲۶-۱۱-۱۴)

این سند تنها دربارهٔ اپ اندرویدی صورتحساب سورا در مخزن `hossean787-blip/Saba-Android` است.

## شواهد معتبر
- شاخهٔ اصلی در آغاز بازبینی: `2ad3f0c2a61c78438a2a897e3dec91b5a4e491d3`.
- نسخهٔ فعلی برنامه در `app/build.gradle.kts`: استاندارد `0.39.0`، `versionCode 39`، بستهٔ `ir.saba.invoice`.
- آخرین APK امضاشدهٔ قابل ردیابی: GitHub Actions run 43181883872 در ۲۰۲۶-۱۱-۱۲، Artifact 13927546552. تغییر پس از آن تا commit مبنا فقط آزمون سروری بوده؛ APK تجاری تأییدشده نیست.
- پروژهٔ مستقل Supabase سورا فعال و نسخه ۱۰ تابع `sura-zarinpal` مستقر است؛ سورس تابع و قواعد آن با GitHub main در زمان بازبینی یکسان بودند.
- بررسی بدون تراکنش واقعی endpoint `/health`: مقدار `merchant_configured=true`. این فقط معتبر بودن شکل شناسهٔ پذیرنده در محیط سرور است، نه موفقیت ارتباط با درگاه.
- پایگاه داده در ۲۰۲۶-۱۱-۱۴: سه سفارش `created`، صفر سفارش `verified`، صفر grant؛ پس یک پرداخت واقعی موفق/تخصیص اعتبار تأیید نشده است.
- ۱۶ جدول عمومی RLS فعال و بدون policy مستقیم هستند؛ از طریق توابع server-owned دسترسی دارند. این وضع به‌تنهایی مجوز اضافه کردن policy باز نیست. هشدار امنیتی Supabase: حفاظت از گذرواژه‌های نشت‌کرده در Auth غیرفعال است.
- تغییر این مرحله: اگر درخواست ساخت تراکنش زرین‌پال خطا بدهد یا پاسخ بدون authority معتبر باشد، سفارش فاقد authority و در وضعیت created به failed تغییر می‌کند. سفارش‌های تاریخی بدون بررسی پرداخت تغییر داده نمی‌شوند.

## موارد مسدودکنندهٔ انتشار تجاری
1. آزمون واقعی و مجاز ارسال، استعلام، احراز رسیدِ معتبر سامانهٔ مؤدیان با مشخصات مؤدی و نسخهٔ رسمی جاری؛ موفقیت Mock یا HTTP به‌تنهایی کافی نیست.
2. پرداخت واقعی کوچک با اجازهٔ مالک پذیرنده، بررسی بازگشت، استعلام و تخصیص اعتبار دقیقاً یک‌بار. IP مجاز خروجی در زرین‌پال/زیرساخت ابر باید تأیید شود.
3. تعیین انطباق سیاست پرداخت فروشگاه مقصد: اعتبار داخل اپ کالای دیجیتال است و ممکن است کافه‌بازار/مایکت پرداخت درون‌برنامه‌ای فروشگاه را لازم بدانند؛ بدون اعلام رسمی فروشگاه، زرین‌پال را مجاز فرض نکنید.
4. نصب ارتقایی روی گوشی کاربر با همان امضای ثابت و بررسی بقای مؤدی، مشتری، فاکتور، فایل و کلید؛ همچنین تست Android Instrumentation روی خروجی نهایی.
5. تأیید عملی ورود/ثبت‌نام/بازیابی، مدیریت چندمؤدی، PDF، انتقال و مصرف اعتبار در سرور، رمز/کلید و عدم نشت داده.
6. تکمیل سیاست حریم خصوصی واقعی، اطلاعات مالک/پشتیبانی، صفحه فروشگاه، تصاویر واقعی، قرارداد توسعه‌دهنده، آزمون امنیت و بازبینی انتشار.

## وضعیت انتشار
- ساخت/آزمون‌های CI: مطابق اجرای مربوط به commit نهایی بررسی شود.
- آمادهٔ پایلوت محدود: تنها پس از تأیید نصب و عملیات غیرمالی واقعی.
- آمادهٔ فروش عمومی: **خیر؛ تا عبور از دروازه‌های بالا.**
- قاعدهٔ حفاظت: هیچ سفارش، پرداخت، دادهٔ مؤدی یا کلید خصوصی واقعی برای آزمون خودکار ایجاد یا در مخزن ذخیره نمی‌شود.
