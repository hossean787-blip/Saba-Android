# دروازه تحویل اضطراری صورتحساب سورا — ۱۴۰۵/۰۸/۱۷

> این سند ثبت وضعیت فعلی است، نه گواهی انتشار تجاری و نه تضمین انجام مراحل آتی.

## محدوده تثبیت‌شده تحویل
- برنامه اندروید مستقل سورا، پنج گردش اصلی: انتخاب مؤدی، انتخاب مشتری، ایجاد/ویرایش/نهایی‌سازی فاکتور، پیش‌نمایش/ذخیره PDF و مدیریت اعتبار.
- حفظ نسخه/داده و کلید امضای نصب‌شده قبلی؛ هیچ حذف داده یا نصب مجدد اجباری مجاز نیست.
- ارسال رسمی فقط برای **صورتحساب اصلی نوع ۱، الگوی فروش ۱، ریالی و نقدی** به‌صورت آزمایشی و با حساب مجاز؛ اصلاحی/ابطالی/برگشت/نسیه/ترکیبی به‌عنوان ارسال رسمی ارائه نشوند.
- خروجی PDF محلی هیچ‌وقت رسید پذیرش سازمان محسوب نمی‌شود.
- هیچ کلید خصوصی، رمز، توکن، گواهی خصوصی یا اطلاعات واقعی مؤدی در مخزن/لاگ یا گزارش عمومی قرار نگیرد.

## تغییر انجام‌شده
- انتخاب مستقیم شناسهٔ ۱۴ رقمی از بانک کالا به فاکتور رد می‌شود؛ مسیر رسمی و راهنماهای موجود شناسهٔ ۱۳ رقمی دارند. منبع ۱۴ رقمی حذف یا به شناسهٔ دیگری تبدیل نمی‌شود.
- دو آزمون regression اضافه شده: رد شناسهٔ ۱۴ رقمی و حفظ صفر پیشرو برای شناسهٔ ۱۳ رقمی.
- بررسی مستقل موقت روی JVM با Kotlin و وابستگی‌های stub انجام شده: ۶ سناریو موفق؛ **این آزمون جایگزین Gradle، Android، JUnit یا امضای APK نیست**.

## کنترل‌های قطعی قبل از تحویل
1. **Build**: روی commit نهایی `main`، اجرای `:app:testDebugUnitTest :app:lintRelease :app:assembleRelease` و ثبت خروجی واقعی؛ هر شکست = توقف تحویل نهایی.
2. **Signature**: تمام چهار secret امضای Release باید در محیط مورد اعتماد تنظیم باشند. `apksigner verify --print-certs` و مقایسه fingerprint با نسخه نصب‌شده؛ نسخه Debug/امضای تصادفی قابل جایگزین شدن نیست.
3. **VersionCode**: اپ استاندارد `25` و نسخه بانک کامل `26` دارد. نصب نسخه `25` روی نسخه نصب‌شده با code `26` ارتقای مجاز نیست؛ قبل از توزیع نسخهٔ نصب‌شده را بخوانید. هیچ downgrade یا uninstall اجباری انجام ندهید.
4. **Upgrade / داده**: نصب `adb install -r` از نسخه قبلی با همان امضا و بررسی واقعی بقای حداقل یک مؤدی، مشتری، صورتحساب، اقلام و PDF؛ ثابت ماندن UID تنها کافی نیست.
5. **فاکتور**: با سناریوهای حداقل دو ردیف، شناسهٔ ۱۳ رقمی، واحدهای متفاوت، مقدار اعشاری، تخفیف و نرخ مالیات متفاوت، محاسبات ردیف/جمع و بازخوانی پس از بستن برنامه را تست کنید.
6. **منفی**: فقدان شناسهٔ کالا، نبود گواهی معتبر، خطای نرخ/جمع/واحد، اتصال قطع‌شده، پیش‌نویس، موضوع اصلاحی، پرداخت نسیه و تکرار درخواست نباید به تأیید ارسال رسمی برسند.
7. **مودیان زنده**: فقط در حساب/محیط مجاز و با دادهٔ مجاز، امضای کلید مؤدی، درخواست رسمی، استعلام همان UID، پاسخ معتبر و `ACCEPTED` با رسید امضاشده را اثبات کنید. تا آن زمان ارسال رسمی «تأییدنشده» است.
8. **خروجی**: APK امضاشده، SHA-256 بسته، SHA-256 گواهی امضا، `versionCode`، نتایج آزمون‌ها، فهرست قابلیت‌های محدود و مسیر بازگشت نسخه آخر سالم.

## مانع اجرایی موجود
- محیط فعلی دسترسی Android SDK 35 و ساخت دستگاه ندارد؛ ساخت APK در این محیط اجرا نشده است.
- مانع تاریخی GitHub Actions مربوط به Billing/سقف مصرف است و هنوز رفع آن بر اساس اجرای موفق جدید اثبات نشده. مالک حساب باید در Settings > Billing وضعیت را تأیید کند؛ تغییر امور مالی بدون اجازه ممنوع است.
- اتصال زنده به مؤدیان و آزمون دستگاه هدف در این نوبت انجام نشده است.

## مسیر ساخت موجود
- GitHub Actions: `.github/workflows/android-signed-release.yml` برای ساخت امضاشده، آزمون، بررسی هویت و آپلود Artifact.
- پیش‌نیاز: JDK 17، Android SDK platform 35 و build tools 34.0.0، keystore قبلی و تنظیمات امضا در محیط حفاظت‌شده.
- پس از رفع محدودیت runner و حضور secrets، workflow روی `main` باید موفقیت را **واقعاً** نشان دهد؛ وجود YAML به‌تنهایی APK تولید نمی‌کند.
