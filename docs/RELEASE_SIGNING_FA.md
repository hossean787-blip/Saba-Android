# امضای پایدار نسخه‌های سورا

## وضعیت
ساخت debug فعلی فقط برای آزمون است و امضای آن برای به‌روزرسانی پایدار قابل اتکا نیست. مسیر «SURA signed APK (manual)» در شاخه main از فایل کلید خصوصی خارج مخزن استفاده می‌کند. هیچ کلیدی در مخزن ذخیره نمی‌شود. تا پیش از تأمین امن کلید و چهار Secret، نسخه انتشار ساخته نمی‌شود.

## گام‌های مالک (نیازمند تصمیم و نگهداری امن)
1. برای نصب‌های آینده یک کلید انتشار دائمی بسازید یا در صورت وجود، **همان کلید نسخه نصب‌شده** را استفاده کنید. از دست دادن کلید امکان به‌روزرسانی مستقیم آن امضا را از بین می‌برد. فایل، گذرواژه‌ها و نسخه پشتیبان را فقط در محل محرمانه نگه دارید.
2. در Settings → Secrets and variables → Actions این چهار Secret را تنظیم کنید: `SURA_RELEASE_KEYSTORE_BASE64` (محتوای base64 فایل .jks)، `SURA_RELEASE_STORE_PASSWORD`، `SURA_RELEASE_KEY_ALIAS`، `SURA_RELEASE_KEY_PASSWORD`. هیچ مقدار یا کلید خصوصی را در Issue، چت عمومی، کد یا Log قرار ندهید.
3. پس از تأیید مالک، از Actions → SURA signed APK (manual) → Run workflow روی main استفاده کنید. خروجی فقط بعد از آزمون، Lint و `apksigner verify` بارگذاری می‌شود.
4. SHA-256 گواهی انتشار را از فایل خروجی نگه دارید و در تمام نسخه‌های بعدی مقایسه کنید؛ علاوه بر ثبات `applicationId`، در نسخه جدید `versionCode` باید افزایش یابد.

## ملاحظات نصب فعلی
امضای debug فعلی با امضای release آینده متفاوت است؛ Android معمولاً نصب مستقیم release روی debug را بدون حذف نسخه قدیمی نمی‌پذیرد. چون کاربر فعلاً داده محلی مهمی ندارد، تنها برای مهاجرت اولیه می‌توان نسخه قدیمی را بعد از تأیید مالک پاک و نسخه پایدار را نصب کرد. پس از آن، به‌روزرسانی‌ها با همان کلید، شناسه بسته ثابت و versionCode افزایشی باید بدون حذف اطلاعات انجام شوند. این سناریو هنوز روی دستگاه واقعی تست نشده است.

## ایمنی
Workflow تنها با اجرای دستی روی main فعال می‌شود. در صورت غیبت Secretها به‌جای انتشار امضانشده شکست می‌خورد. فایل موقت کلید با مجوز محدود ساخته و در پایان مرحله پاک می‌شود. به هیچ وجه فایل JKS را Commit نکنید.
