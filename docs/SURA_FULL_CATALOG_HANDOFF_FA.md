# گزارش اجرایی — بانک کامل شناسه کالا و خدمات در سورا

تاریخ: ۱۴۰۵/۰۸/۱۵ (۶ نوامبر ۲۰۲۶)
مخزن: hossean787-blip/Saba-Android
شاخه: main
دامنه این مأموریت: فقط بانک شناسه کالا/خدمات و نصب آفلاین آن در سورا.

## واقعیت داده‌ها
- مبنا: هر ۹ فایل CSV کنترل‌شده و بایگانی‌شده در همین پروژه.
- رکوردهای ورودی: ۷٬۳۳۰٬۱۰۷؛ بانک فعال: ۴٬۲۲۷٬۲۱۸ شناسه یکتا.
- اطلاعات تاریخی/تکراری در آرشیو اولیه محفوظ مانده است، اما بانک فعال فقط رکورد منتخب هر شناسه را دارد.
- خروجی فشردهٔ تعبیه‌شدنی: ۱۴ فایل gzip + manifest.json.
- حجم مجموع قطعات فشرده: ۶۴۲٬۹۴۴٬۹۴۸ بایت.
- حجم دیتابیس پس از استخراج: ۱٬۸۳۰٬۷۶۴٬۵۴۴ بایت.
- SHA-256 دیتابیس: 567fbba0e54a863879c790a848866a7e16d48ad272c66e286172f87b67fd0e9f.
- ایندکس جستجوی فارسی FTS4 به فرم contentless تبدیل شده است تا داده‌های متنیِ تکراری در دیتابیس دوباره ذخیره نشوند.
- نکته فنی: PRAGMA quick_check برای FTS4 contentless نمی‌تواند متن ذخیره‌نشده را بازخوانی کند و هشدار می‌دهد؛ صحت با هش کامل دیتابیس، تطبیق ۱۴ بخش و آزمون جستجوی واقعی کنترل شده است.

## تغییرات برنامه
- SuraBundledCatalogInstaller.kt: تشخیص بانک همراه APK، استخراج آفلاین مرحله‌ای با کنترل SHA-256، کنترل فضای آزاد، نصب اتمیک با حفظ بانک قبلی و بازیابی پس از خطا.
- SuraIdentifierScreen.kt: فعال‌سازی خودکار در اولین ورود به بخش شناسه‌ها، نمایش پیشرفت و حذف نیاز به انتخاب دستی ZIP وقتی بانک داخلی فعال شده است.
- app/build.gradle.kts: عدم فشرده‌سازی مجدد فایل‌های gzip در APK؛ شماره نسخه مخصوص Release کامل، 0.18.0 (versionCode=18) با -PsuraEmbeddedFull=true.
- scripts/verify-sura-bundled-catalog.py: ردکردن خروجی ناقص یا دستکاری‌شده.
- .github/workflows/sura-embedded-full-release.yml: ساخت دستی و امضای APK کامل فقط پس از دریافت Artifact داده و تطبیق بانک داخل APK.
- .gitignore: داده‌های حجیم عمداً در مخزن عمومی ثبت نمی‌شوند.

## آزمون و وضعیت
- آزمون SQLite: تعداد رکوردها، تطبیق نمونه‌ها با منبع، جستجوی شناسه و FTS4 موفق.
- همه ۱۴ بخش gzip بازخوانی شدند؛ SHA-256 کل خروجی با دیتابیس مبنا یکسان بود.
- ZIP بسته داده‌ای ۱۷ عضو دارد؛ آزمون CRC بدون خطا.
- آزمون نصب روی گوشی و APK واقعاً حاوی بانک کامل **انجام نشده**.
- نبود داده‌ها در Git باعث می‌شود APKهای CI عادی هنوز سبک و فاقد بانک داخلی باشند. صرفاً کد نصب خودکار در آن‌ها وجود دارد.

## مانع واقعی و اقدام بعدی
انتقال قطعات داده به محیط امضای GitHub Actions هنوز انجام نشده است. ابزار GitHub متصل به این نشست API بارگذاری باینری بزرگ به Artifact را ارائه نمی‌کند؛ فایل خروجی ۶۴۳ مگابایت است و فرستادن این داده به مخزن عمومی بدون درنظرگرفتن حق انتشار و هزینه نگهداری انجام نشده است.

پس از فراهم‌شدن یک Artifact مجاز با نام sura-full-catalog-assets در مخزن، ورک‌فلو «SURA FULL embedded identifiers — signed update» با شناسه آن اجرا شود. این ورک‌فلو:
۱. بانک و همه هش‌ها را کنترل می‌کند؛
۲. آزمون‌های JVM را اجرا می‌کند؛
۳. APK نسخه 0.18.0 را با امضای قبلی می‌سازد؛
۴. وجود قطعات داخل خود APK را کنترل می‌کند؛
۵. فقط فایل امضاشده تأییدشده را به‌عنوان Artifact ذخیره می‌کند.

تا قبل از تأیید این پنج مورد، نسخه «کامل با بانک داخلی» منتشرشده تلقی نمی‌شود.
